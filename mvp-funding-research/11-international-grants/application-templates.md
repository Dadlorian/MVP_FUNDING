# International Grant Application Templates

## Overview
Narrative structure templates and work package examples for EU, UK, Canadian, and other international funding programs. Includes realistic examples demonstrating how to structure compelling project descriptions.

---

## 1. EU Horizon Europe - Generic Narrative Template

### Section A: Excellence

#### A.1 Concept and Objectives

**Word Limit**: 3,000 words
**Key Elements**: Vision, scientific/technical challenge, objectives, impact hypothesis

**Template Structure**:

```
VISION & BACKGROUND
[2-3 paragraphs describing the overarching challenge]

The global challenge of [FIELD] is increasingly critical for [SOCIETAL/ECONOMIC IMPACT].
Current state-of-art approaches [DESCRIBES EXISTING SOLUTIONS] but face fundamental
limitations: [LIST LIMITATIONS]. This creates an opportunity for [INNOVATIVE APPROACH].

Our vision for [PROJECT NAME] is to [CLEAR, INSPIRING STATEMENT OF TRANSFORMATIVE IMPACT].

SCIENTIFIC & TECHNICAL CHALLENGE
[Detailed explanation of what makes this difficult]

Core challenges include:
1. Technical Challenge 1: [Description with relevant citations] (Literature gap: [X])
2. Technical Challenge 2: [Specific barrier preventing current solutions]
3. Integration Challenge: [How sub-problems interconnect]

We position our approach as novel because [DIFFERENTIATION FROM EXISTING WORK].

RESEARCH OBJECTIVES & HYPOTHESES
[5-7 specific, measurable objectives]

Primary Objective (O1): [MEASURABLE TARGET]
- Hypothesis: [What we believe to be true and will test]
- Success criteria: [How we measure achievement]
- Timeline: [When we expect results]

Secondary Objective (O2): [Related but distinct objective]
- Hypothesis: [Mechanistic understanding / proof-of-concept]
- Success criteria: [Specific metrics]
- Relevance: [How this supports O1 or broader impact]

[Continue for O3-O7]

INNOVATION & ADVANCEMENT
[How this moves beyond current state-of-art]

Current state: [Literature review of existing approaches]
Our innovation: [Specific novel elements]
- Methodological innovation: [New technique/approach]
- Technical innovation: [New tools/systems]
- Integration innovation: [New combinations of existing elements]

Expected advancement: [Quantitative improvement targets]

IMPACT HYPOTHESIS
[Logic model from research to real-world impact]

Research Output → Development Output → Real-world Impact

[Describe causal chain with intermediate milestones]
```

## 4. Work Package Example: EU Horizon Application

```
WORK PACKAGE 2: AI MODEL DEVELOPMENT & OPTIMIZATION (WP2)
Lead Organization: TechCorp Ltd (Germany)
Start Date: M1 | Duration: 24 months | End Date: M24
Budget: €680,000
Work Package Responsible: Dr. Anna Schmidt (TechCorp)

OBJECTIVES
WP2.1: Develop deep learning architecture for multi-modal data integration
WP2.2: Optimize model performance against clinical benchmarks
WP2.3: Implement privacy-preserving mechanisms compliant with GDPR
WP2.4: Create software framework for federated learning deployment

DESCRIPTION OF WORK

Task 2.1: Architecture Design & Literature Review (Months 1-4)
  Subtask 2.1.1: Systematic literature review on [topic]
    - Responsible: Research Scientist (0.5 FTE)
    - Output: Review paper with architecture recommendations
    - Deadline: Month 3
    - Dependencies: None

  Subtask 2.1.2: Preliminary architectural designs (3 candidate architectures)
    - Responsible: Senior Researcher (0.3 FTE)
    - Output: Design specifications document, decision matrix
    - Deadline: Month 4
    - Dependencies: 2.1.1 completion

  Subtask 2.1.3: Feasibility analysis & prototype development
    - Responsible: Software Engineer (0.8 FTE)
    - Output: Proof-of-concept code, technical report
    - Deadline: Month 4
    - Dependencies: 2.1.2 completion

Task 2.2: Core Model Development (Months 3-12)
  [Description of development work, using same structure]

Task 2.3: Validation & Optimization (Months 10-18)
  [Description of testing and refinement]

Task 2.4: Privacy & Security Implementation (Months 15-24)
  [Description of GDPR/security hardening]

Task 2.5: Software Release & Documentation (Months 20-24)
  [Description of software engineering, documentation]

DELIVERABLES

D2.1: Literature Review & Architecture Specification [Deadline: M4]
  Type: Report
  Description: Systematic review of multi-modal learning architectures in medical AI, with
    specification of chosen architecture and justification
  Acceptance Criteria:
    - Comprehensive review covering >50 relevant publications
    - Architecture specification with detailed technical specifications
    - Comparison matrix of alternatives considered
    - Decision rationale documented
  Dissemination: Public (via project website)
  Lead: TechCorp, Contribution from UniversityA

D2.2: Initial Model Development Code Release [Deadline: M8]
  Type: Software
  Description: Open-source implementation of core model architecture with training pipeline
  Acceptance Criteria:
    - Code follows open-source standards (PEP 8, documented)
    - Unit tests with >80% code coverage
    - Builds successfully in standard Python environment
    - Detailed README and API documentation
    - Example training script with sample data
  Dissemination: Public (GitHub repository)
  Lead: TechCorp

D2.3: Model Performance Benchmarking Report [Deadline: M14]
  Type: Report
  Description: Detailed evaluation of model performance against state-of-art methods
  Acceptance Criteria:
    - Evaluation on standard benchmark datasets
    - Comparison with >5 competing methods
    - Performance metrics for precision, recall, F1, AUC
    - Error analysis documenting failure modes
    - Recommendations for further optimization
  Dissemination: Public (published as research article)
  Lead: UniversityA, Lead by TechCorp

D2.4: Privacy-Preserving Implementation [Deadline: M22]
  Type: Software
  Description: Integration of differential privacy and federated learning capabilities
  Acceptance Criteria:
    - Differential privacy implementation with configurable epsilon parameters
    - Federated learning framework supporting >3 data sites
    - Privacy impact assessment documentation
    - GDPR compliance checklist completed
    - Example deployment scenario with simulated multi-site scenario
  Dissemination: Public (GitHub, with academic paper)
  Lead: TechCorp, Contribution from PrivacyConsultant

D2.5: Software Release & User Documentation [Deadline: M24]
  Type: Software + Documentation
  Description: Production-ready software package with comprehensive documentation
  Acceptance Criteria:
    - Stable v1.0 release on PyPI/GitHub
    - User guide for model training, evaluation, deployment
    - API reference documentation
    - Tutorial Jupyter notebooks with examples
    - Troubleshooting guide
    - Installation guide for different operating systems
  Dissemination: Public
  Lead: TechCorp

DEPENDENCIES WITH OTHER WORK PACKAGES

Inputs from Other WPs:
- Data standards & specifications from WP1 (due M2) required for data preprocessing pipeline
- Clinical validation protocol from WP3 (due M6) informs evaluation metrics
- Requirement specifications from WP1 (due M3) constrain architectural choices

Outputs to Other WPs:
- Model framework delivered to WP3 (M8) for validation studies
- Trained model weights delivered to WP4 (M18) for clinical deployment
- Documentation delivered to WP5 (M20) for training & dissemination

Iteration with Other WPs:
- WP3 validation results (M14) feed back into WP2 optimization (M14-M18)
- WP4 deployment feedback (M18-M24) may trigger model refinements

MANAGEMENT
```

## 5. Reviewer-Friendly Proposal Checklist

Before submission, verify:

- [ ] **Clarity**: Can a specialist in the field understand the proposal without domain expertise?
- [ ] **Novelty**: Is innovation clearly articulated and differentiated from prior work?
- [ ] **Feasibility**: Timeline realistic? Team has right expertise? Resources appropriate?
- [ ] **Impact**: Clear pathway from research to real-world impact? Metrics defined?
- [ ] **Management**: Governance structure appropriate? Risks identified? Contingencies in place?
- [ ] **Budget**: Justified and realistic? Aligns with scope and timeline?
- [ ] **Team**: Track record demonstrated? Roles clear? Complementary expertise?
- [ ] **Structure**: Follows funder template exactly? Page limits observed? Citations appropriate?
- [ ] **Quality**: No typos/grammar errors? Figures legible? Tables properly formatted?
- [ ] **Compliance**: Meets all program requirements? Ethics/safety addressed? Data management plan included?
